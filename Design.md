## Design Direction

This document defines the visual direction, interaction philosophy, and overall user experience principles of the platform.

The goal is not to create a generic dashboard.

The goal is to create a modern geospatial intelligence platform that feels trustworthy, informative, and visually distinctive.

---

# 1. Design Philosophy

StormScope should feel like a combination of:

- Modern cartography
- Environmental intelligence platforms
- Satellite visualization systems
- Research-grade analysis tools

The user should immediately understand that the platform deals with geography, weather systems, infrastructure, and environmental risk.

The interface should feel calm and authoritative rather than aggressive or futuristic.

---

# 2. Emotional Tone

The platform should communicate:

### Confidence

The system presents information clearly without exaggerated claims.

### Clarity

Users should understand outputs quickly.

### Exploration

Maps and visualizations should encourage investigation and discovery.

### Professionalism

The platform should resemble a modern analytical tool rather than a student project.

---

# 3. Visual Identity

The visual system should draw inspiration from:

- Earth observation imagery
- Satellite photography
- Ocean and coastline mapping
- Meteorological visualizations
- Terrain analysis systems

Avoid:

- Neon cyberpunk palettes
- Purple AI gradients
- Overly dark interfaces
- Excessive glassmorphism
- Gaming aesthetics
- Blockchain-inspired visuals

---

# 4. Colour Direction

The colour palette should be derived from natural environmental systems.

### Deep Ocean

Primary background surfaces.

Represents:

- Bay of Bengal
- Ocean depth
- Cyclone origins

### Coastal Blue

Primary interactive colour.

Represents:

- Water
- Forecast tracks
- User actions

### Monsoon Teal

Secondary accent.

Represents:

- Coastal environments
- Observational data
- Environmental monitoring

### Terrain Sand

Used sparingly.

Represents:

- Land
- Elevation
- Geographic features

### Warning Amber

Used for cautionary indicators.

### Hazard Red

Used only for high-risk visualization.

Never use red as a primary brand colour.

---

# 5. Atmosphere

The interface should feel like:

A storm being observed from orbit.

Not:

A storm being experienced from inside it.

This distinction is important.

The platform provides analysis and understanding.

It does not attempt to create drama.

---

# 6. Layout Principles

All major screens should follow:

Header

↓

Primary Summary Layer

↓

Map Layer

↓

Analysis Layer

↓

Supporting Information

Maps should always occupy significant screen space.

Maps are the primary content.

Cards support the maps.

Cards should never dominate the screen.

---

# 7. Landing Page

The landing page should tell a story.

### Section 1

Hero

Large statement.

Background:

Animated cyclone trajectory.

---

### Section 2

Problem Statement

Explain fragmentation of historical cyclone information.

---

### Section 3

Platform Overview

Explain how the system combines datasets.

---

### Section 4

Capabilities

Hazard Assessment

Exposure Analysis

Infrastructure Planning

---

### Section 5

Interactive Preview

Dashboard preview.

---

### Section 6

Methodology

Simple workflow visualization.

---

### Section 7

Project Background

Academic context.

---

# 8. Dashboard Experience

The dashboard should prioritise speed of understanding.

The first screen should answer:

What happened?

Where did it happen?

What was exposed?

What does it mean?

Users should not need to scroll before finding value.

---

# 9. Maps

Maps are the most important interface element.

Maps should occupy between 40% and 70% of visible dashboard space.

The map should feel alive but not busy.

Layers should turn on progressively.

Animation should reveal information rather than distract from it.

---

# 10. Cards

Cards should feel lightweight.

Cards are containers for:

- Metrics
- Insights
- Recommendations
- Explanations

Cards should support the map.

Not compete with the map.

---

# 11. Motion

Motion should communicate:

- Transitions
- Focus changes
- State changes

Motion should never exist only for decoration.

Animations should feel:

- Smooth
- Natural
- Deliberate

Avoid:

- Bouncing
- Overshooting
- Dramatic zoom effects

---

# 12. Construction Assessment

This page should feel different from the dashboard.

It should resemble a planning workstation.

The visual focus should be:

Location

↓

Historical Exposure Indicators

↓

Assessment Summary

↓

Development Guidance

Use more whitespace than other pages.

This page should feel analytical.

---

# 13. Mobile Experience

Maps remain the primary element.

Cards stack below maps.

Charts appear below key metrics.

No feature should be desktop-only.

---

# 14. Final Design Rule

Whenever a visual decision must be made, choose the option that makes the platform look more like:

A modern environmental intelligence platform.

Not:

A startup landing page.

Not:

An AI application.

Not:

A generic admin dashboard.
